## Change evidence

This release ships the archived proposal `add-archive-evidence-recovery`
(修 bug, 6/6 tasks, TDD failing-regression-first):

- One archive directory missing terminal status and `.sdd/` evidence used to
  block the derived INDEX rebuild of every subsequent archive
  (`COMMITTED_DERIVED_ARTIFACT_STALE`), while the recovery reference forbade
  the only manual workaround; the 2026-07-26 incident is pinned as a
  regression in `tests/test_archive_recovery.py`.
- `repair-archive-record` adds the supported path: a read-only preflight
  reports the missing records and prints labeled raw-byte evidence digests;
  explicitly confirmed execution fills only missing fields, records the
  summary as recovery evidence v1, and never moves directories, never guesses
  summaries, and never changes an existing correct record. Evidence drift and
  suffix/status disagreement fail closed
  (`ERROR_RECOVERY_EVIDENCE_MISMATCH` → `rerun_repair_preflight`,
  `ERROR_RECOVERY_STATUS_MISMATCH` / `ERROR_RECOVERY_TARGET_INVALID` /
  `ERROR_RECOVERY_NOT_APPLICABLE` → `inspect_archive_state`).
- `rebuild-index --directory NAME --summary TEXT` accepts an explicitly
  provided summary only when the directory has no summary source, removing
  the circular dependency on an existing INDEX row
  (`ERROR_RECOVERY_SUMMARY_UNEXPECTED` otherwise).
- `SKILL.md` command list, `references/runtime-recovery.md` (new archive
  record recovery procedure and `rerun_repair_preflight` binding action),
  `docs/cli-contract.md`, `docs/archive-model.md` (recovery evidence v1), and
  `docs/doctor-diagnostics.md` were synchronized; the CLI snapshot fixture,
  conformance manifest, testing map, and package validation registered the
  new surface.

## SemVer and scope review

Versioning policy §2 classifies this release as MINOR: it adds a
backward-compatible optional command, optional `rebuild-index` arguments, and
new diagnostic codes without changing existing authority, stop boundaries,
defaults, or required consumer behavior. Engine generation advances to `1.1`;
proposal schemas v1/v2, JSON output v1, every machine-envelope version, all
existing commands, and the archive/INDEX authority model are unchanged. The
v0.6 baseline test now pins that historical inventory explicitly and asserts
the live inventory remains a superset.

The staged release contains no raw Agent transcripts, secret-bearing eval
artifacts, absolute user paths, or unrelated working-tree changes.
