# v0.10 controlled team trial

Status: controlled aggregate, not production telemetry

The trial uses two anonymous logical operators, three sessions, two proposals,
and separate Git worktrees. One proposal includes a fresh-status handoff
between the logical operators. Six snapshot-controlled lifecycle mutations
complete through the public CLI. The trial then removes one derived INDEX,
rebuilds it, validates it, and requires a healthy doctor result.

Run:

```text
python3 scripts/run-team-evidence-trial
```

The versioned aggregate is
[`evals/team-trials/v010-controlled-trial-v1.json`](../../evals/team-trials/v010-controlled-trial-v1.json).
It records:

- multi-operator proposals: 1/2;
- same-proposal concurrent mutation attempts: 0/6;
- stale snapshot results: 0/6;
- short-name conflicts: 0/2 creation attempts;
- stale/conflicting derived INDEX observations: 1/3 terminal or INDEX events;
- isolated worktree runs: 1/1;
- recovery interventions: 1/1 observed incident; and
- managed-workflow bypass observations: 0/6 lifecycle operations.

The INDEX deletion is a deliberate derived-state recovery observation, not an
authoritative-state bypass. No raw proposal content, transcript, operator
identity, local path, or machine identity is retained.

This sample is evidence that the current cooperative operating model and
documented recovery path work in a bounded hermetic trial. It is not evidence
of production adoption frequency or a human-population incident rate.
