## Change evidence

This release adds conditional engineering evidence to the workflow: proposal
tasks prefer dependency-ordered vertical outcomes; approved tasks begin with a
minimum context packet; version-dependent decisions require the project's
version evidence and official documentation; and completion applies only
relevant Definition of Done standards explicitly declared by the project.

The Chinese and English READMEs, proposal-authoring reference, runtime identity,
tests, and CHANGELOG document the same boundaries. The archived proposal
`add-engineering-quality-gates` records the completed scope and acceptance
evidence.

## SemVer and scope review

Versioning policy §2 classifies this release as MINOR because it adds
backward-compatible conditional engineering guidance without changing existing
lifecycle authority, defaults, schemas, CLI commands, or machine envelopes.

Engine generation advances to `1.3`; proposal schemas v1/v2, JSON output v1,
discovery/handshake versions, and every machine-envelope version remain
unchanged. Existing proposals require no migration, and pinning the complete
v1.2.0 package remains a direct rollback before using the new guidance.

The staged release contains no raw Agent transcripts, credentials, absolute
user paths, or unrelated working-tree changes. No file under `eval-runs/` is
staged; raw run artifacts remain ignored.
