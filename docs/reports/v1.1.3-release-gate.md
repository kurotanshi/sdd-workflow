## Change evidence

This release adds conditional implementation-readiness guidance to proposal
authoring. Complex or high-risk work records the source of truth, commit point,
retry/recovery behavior, and non-repeatable side effects in existing proposal
artifacts. Small low-risk work continues to draft directly. The contributor
acceptance matrix documents the same boundary in English and Chinese.

The change is instruction- and documentation-only. It adds one anchor test for
the bounded guidance and does not change runtime code paths, lifecycle state,
approval authority, trigger rules, schema, commands, or JSON output.

## SemVer and scope review

Versioning policy §2 classifies this release as PATCH. The authoring guidance
clarifies when existing proposal fields must carry implementation-readiness
facts; it does not require new reader behavior or change a public machine
contract.

Engine generation remains `1.1`; proposal schemas v1/v2, JSON output v1,
discovery/handshake versions, and every machine-envelope version remain
unchanged. The release contains no Schema v3, locking or lease system, Web UI,
external-platform integration, or multi-Agent orchestration.

The staged release contains no raw Agent transcripts, credentials, absolute
user paths, or unrelated working-tree changes. No file under `eval-runs/` is
staged; raw run artifacts remain ignored.
