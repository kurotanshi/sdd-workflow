# 實作 (Implement)

當使用者執行 `/implement` 時，代表要進入「提案 → 實作 → 歸檔」流程的第二階段，通常在使用者確認過 `/propose` 產出的 proposal.md/tasks.md 之後才會呼叫。

如果目前工作目錄的 `sdd/` 下有多個資料夾的 `tasks.md` 還有未打勾（`- [ ]`）的項目，且使用者沒有指定短名稱，先問使用者要實作哪一個；如果只有一個未完成的，直接使用它。

## 你要做的事

1. 讀 `sdd/<短名稱>/proposal.md` 和 `tasks.md`，搞清楚要做什麼
2. 從上到下，**一次只做 `tasks.md` 裡的一條 `- [ ]` 任務**。每做一條之前，先看看專案裡有沒有現成的東西可以重複使用，不要重複造輪子
3. 做完一條之後，在打勾之前回頭再讀一次那條任務和 `## 驗收條件`，確認真的做到了、沒有漏。確認沒問題就把該條的 `- [ ]` 改成 `- [x]`。改完後再看一眼 `tasks.md`，確認那一行真的變成 `- [x]` 了
4. 每完成一條就簡短回報「第幾條完成」，然後做下一條
5. 如果做到一半發現規格漏了東西或方向不對，**停下來告訴使用者，等使用者決定，不要自己亂改規格、也不要硬幹**
6. 全部打勾後，告訴使用者「全部完成」，並請使用者驗收

## 額外參數

$ARGUMENTS

（可留空；若有內容，視為指定要實作哪個短名稱，或使用者針對某一條任務的補充說明）
